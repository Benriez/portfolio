# BODI runtime

The portfolio contains a **deterministic visualization** of Agent Garden's
BODI semantics. It is **not** the real runtime. There is no live agent
process, no SQLite database, no Telegram bridge, no production kernel.

## What this is

A small TypeScript island that animates a token along a fixed graph drawn
with SVG. Every aspect of the visualization is verifiable from the source:

- The graph layout is computed by `geometry.ts`.
- The labels are static data in `labels.ts`.
- The progression is generated by a pure state machine in `machine.ts`.
- The DOM adapter is `BodiRuntimeVisualization.astro`.

## Why include it

The portfolio is for an engineer who spends a meaningful share of his time
on Agent Garden. A picture is a more honest CV than prose: it shows that the
mental model is shared and inspectable, not a slogan.

## Verified concepts (canonical source = Agent Garden master branch)

The visualization is derived from concepts revalidated against the canonical
Agent Garden bridge code. The shapes of the graph reflect how a real run
moves. Names may differ in trivial ways; mapping is one-to-one at the
mechanism level.

The Agent Garden repo is a sibling of this portfolio and lives in the
operator's source tree. We reference its bridge code (e.g. the verifier at
`services/workflow-controller/verifier.ts`) by stable function name and
file path inside that repo. We do **not** record any absolute on-disk
locations in this portfolio.

| Visualization node | Agent Garden mechanism                                              |
| ------------------ | ------------------------------------------------------------------- |
| Graph node active  | Current `WorkflowNode` cursor in `controller.tick(run)`             |
| Agent tick         | `async tick(run)` — one node per call                               |
| Verification       | Mutation-evidence validator — pass / fail classification            |
| Pass               | `BODI_NODE_RESULT_V1` accepted; persist continues                   |
| Fail               | Validator declined; recovery engages                                |
| Recover            | `BODI_RECOVERY_REQUIRED` route                                      |
| Supervisor         | TypeScript supervisor (`supervisor-recovery-runtime.ts`)            |
| Bounded attempts   | Attempt budget; `attemptCount >= MAX_ATTEMPTS` → `terminal_failure` |
| Persist            | `mutation-evidence` commit                                          |
| Continue           | `BODI_GRAPH_CONTINUE` or resume on next runtime pass                |
| Terminal failure   | `attemptCount >= 3` boundary — no further persist                   |

`MAX_ATTEMPTS` is currently 3 and matches Agent Garden's verifier
inside `services/workflow-controller/verifier.ts`.

The exact verbal labels may differ by mode (HR / Engineering) but the node
identifiers and edge topology are stable. If Agent Garden semantics change,
the corresponding `src/features/bodi-runtime/` files are the single point
of update.

## Normal flow

```
graph-active → tick → verify → pass → persist → continue
```

Tokens traverse the upper rail. After a successful cycle, the cursor returns
to a fresh graph-active node and the cycle restarts.

## Recovery flow

```
fail → recover → supervisor → bounded-attempt → verify
```

When verification fails, recovery and supervisor engage. The bounded-attempt
budget is consumed until either:

- the retry passes (return to the normal flow), or
- the budget is exhausted.

## Failure boundary

**The visualization does NOT model:**

- `failed verification → retry exhausted → successful persist`

If the bounded attempt budget is exhausted, the run enters **terminal**
failure. The graph lights the `exhausted` node, the meta panel shows the
current attempt number, and the run does not progress. The normal
demonstration cycle intentionally recovers in time, so the user sees the
recovery branch in its working form.

## State-machine architecture

`machine.ts` is **pure TypeScript**:

- No DOM, no timers, no `requestAnimationFrame`, no `MutationObserver`.
- Exposes `initialState`, `initialFrame()`, and `advance(state) -> {state, frame}`.
- Frame data is fully testable from the unit suite (`tests/unit/machine.test.ts`).

`controller.ts` (referenced from `BodiRuntimeVisualization.astro`) owns:

- The DOM references to `[data-bodi-runtime]`, `[data-runtime-svg]`, `[data-runtime-edges]`, etc.
- The tick interval (`TICK_MS` = 1.1 s; `REDUCED_MOTION_TICK_MS` = 2.2 s).
- The `MutationObserver` that re-renders when `body[data-mode]` changes.
- Reduced-motion short-circuit (no interval starts; static state shown).

`geometry.ts` is **pure**:

- Takes a list of node bounds (in a virtual coordinate system).
- Returns a `RuntimeGeometry` describing the graph and edges.
- Viewport-aware scaling is the only environmental input.
